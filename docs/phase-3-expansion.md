## Implemented integrations

### Shared PHP family

One configurable adapter now covers Lagazuoi, Croda da Lago, Coldai,
Carestiato, Tissi, Passo Duran, and Vazzoler. It posts only arrival, departure,
and party size to each official first-step search. A positive result requires a
`prenotazione2.php` next-step form and selectable quantities whose combined
capacity covers the party. The adapter never submits that second form.

Explicit multilingual no-inventory responses are distinguished from unknown
markup. A configured official opening date takes precedence over a booking
system's generic pre-opening sold-out placeholder.

### Bukly family

The Playwright adapter now accepts registry configuration for Averau, Col
Gallina, and Scotoni. It distinguishes a future release frontier from an
isolated disabled date and rejects Bukly's suggested alternatives as positive
availability. It does not click a room's `Seleziona` button.

### Individual systems

- Scoiattoli reproduces the hidden ISO fields generated by its date picker. It
  evaluates the selected-date result before any alternative-date suggestion.
- Nuvolau caches one official monthly response and sums `data-units-left`
  across its bed-based dormitory types. Its published January 2027 opening date
  currently prevents zero-filled pre-opening calendars from being called sold
  out.
- Dibona calls only the browser application's read-only `/api/search` endpoint.
  It explicitly does not call `/api/booking-hold`, which would hold inventory.
- Booking Südtirol failures at both Lavarella and Fanes remain
  `cannot_determine`. The monitor does not bypass the browser's CORS protection.

## Range scanner and reports

The `scan` command expands the inclusive configured range into exactly 36
one-night checks. Requests are serialized with a configurable delay per host.
Checker instances are reused, allowing Nuvolau to cache its two monthly pages.

Booking opening and three-person inventory remain independent. Any conclusive
searchable result—available, insufficient, or fully booked—proves the season is
open. A mixture containing errors remains `unknown`, rather than being reduced
to `not_open`.

A live three-night Coldai smoke scan produced normalized JSON, a date matrix
CSV, and a Markdown summary in the local runtime artifacts. Equivalent files
are uploaded by every hosted workflow run and persisted on `monitor-state`.

All three nights returned verified three-person availability and the separate
opening state `open`.

The 26-test suite covers the shared parsers, alternative-date rejection,

## Remaining limitations

- Booking Südtirol is unusable on both official embedding sites at verification
  time. A direct third-party result is not substituted for the broken official
  flow.
- The Nuvolau positive path is fixture-tested but cannot be validated live
  until its announced January opening.
- Bukly range scans currently create a fresh browser for each night. This is
  correct but too expensive for hourly production use; Phase 4 must reuse a
  browser session or authoritative network responses before scheduling it.
- The eight contact/request-only accommodations cannot satisfy the strict
  automated verification standard. Page-change monitoring could be added as a
  separately labeled advisory signal, never verified availability.
- Public markup and undocumented APIs can change. Unknown responses remain
  `cannot_determine` and do not overwrite a prior successful observation once
  persistence is added.

## Phase 4 boundary

Phase 4 should add persistent snapshots and transition reduction first, then
GitHub Issue notifications and the hourly/manual Actions workflow. It must also
batch browser work before enabling the hourly schedule. No notification should
be sent merely because Phase 3 established an already-open baseline.
